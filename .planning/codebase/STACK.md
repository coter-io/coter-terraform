# Technology Stack

**Analysis Date:** 2026-08-21

## Languages

**Primary:**
- HCL (Terraform) - Infrastructure definitions in `infra/terraform/`
- Bash (POSIX-ish, `bash`/`set -euo pipefail` style) - All operational tooling in `deploy/*.sh`, `scripts/*.sh`, `config/inputs.example.sh`

**Secondary:**
- YAML (cloud-init / `#cloud-config`) - `infra/cloud-init/user-data.yml.tpl`, templated with Terraform `templatefile()` interpolation (`${...}`, `%{ if }`)
- Makefile (GNU Make) - `Makefile` at repo root, orchestrates all commands

This repository is infrastructure-as-code only; it provisions and operates a VPS that runs the separate "OpenClaw" application (pulled from GHCR as Docker images, sourced from a sibling `openclaw-config` repo referenced via `CONFIG_DIR`). No application source code (Node/Python/etc.) lives in this repo.

## Runtime

**Environment:**
- Terraform CLI `>= 1.5` (declared in `infra/terraform/globals/versions.tf` and `infra/terraform/envs/prod/main.tf`)
- Target VPS OS: Ubuntu (cloud-init uses `apt-get`, `lsb_release`, `ufw`) - see `infra/cloud-init/user-data.yml.tpl`
- Docker Engine + `docker-compose-plugin` installed on the VPS via cloud-init (`docker-ce`, `docker-ce-cli`, `containerd.io`, `docker-buildx-plugin`, `docker-compose-plugin`)

**Package Manager:**
- No language package manager (no npm/pip/cargo) — this repo has no application dependency manifest.
- Terraform provider dependency lock: `.terraform.lock.hcl` is generated by `terraform init` (not committed; see `.gitignore`).

## Frameworks

**Core:**
- Terraform (HashiCorp) - IaC provisioning framework, `infra/terraform/`
- cloud-init (`#cloud-config`) - first-boot VPS provisioning, `infra/cloud-init/user-data.yml.tpl`

**Testing:**
- None (no automated test suite). `make validate` runs `terraform validate` plus `bash -n` syntax checks on all `deploy/*.sh` and `scripts/*.sh` files (see `Makefile`).

**Build/Dev:**
- GNU Make - `Makefile` (targets: `init`, `plan`, `apply`, `destroy`, `fmt`, `validate`, `ssh`, `ssh-root`, `tunnel`, `output`, `ip`, `bootstrap`, `deploy`, `push-env`, `push-config`, `setup-auth`, `backup-now`, `restore`, `logs`, `status`, `tailscale-*`, `workspace-sync`)
- `terraform fmt -recursive infra/` for formatting

## Key Dependencies

**Critical:**
- Terraform provider `hetznercloud/hcloud` `~> 1.45` (`infra/terraform/globals/versions.tf`, `infra/terraform/envs/prod/main.tf`, `infra/terraform/modules/hetzner-vps/main.tf`) - manages all Hetzner Cloud resources (server, firewall, ssh key lookup)

**Infrastructure:**
- Docker Compose (v2 plugin, invoked as `docker compose`) - used by `deploy/deploy.sh`, `deploy/restore.sh`, `deploy/status.sh`, `deploy/logs.sh`, `scripts/setup-auth.sh` to manage the OpenClaw application containers on the VPS. The actual `docker-compose.yml` lives in the external `openclaw-config` repo (`$CONFIG_DIR/docker/docker-compose.yml`), not in this repo.
- UFW (Uncomplicated Firewall) - host-level firewall configured by cloud-init, layered under the Hetzner Cloud Firewall
- systemd timers - used for scheduled backup (`deploy/backup.sh`) and workspace git-sync, set up by `deploy/bootstrap.sh`

## Configuration

**Environment:**
- `config/inputs.sh` (gitignored, copied from `config/inputs.example.sh`) - exports all `TF_VAR_*`, `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` (S3 backend creds), `HCLOUD_TOKEN`, `GHCR_USERNAME`/`GHCR_TOKEN`, `CONFIG_DIR`, `CLAUDE_SETUP_TOKEN`, Tailscale vars, and server overrides. Must be `source`d before running `terraform`/`make` targets.
- `secrets/openclaw.env` (gitignored, copied from `secrets/openclaw.env.example`) - application-level secrets pushed to the VPS via `scripts/push-env.sh` (`ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`, `OPENCLAW_GATEWAY_TOKEN`, `GHCR_USERNAME`, `GH_TOKEN`, `BRAVE_API_KEY`, `GIT_WORKSPACE_*`).
- Terraform variables declared per-environment in `infra/terraform/envs/prod/variables.tf` (e.g. `hcloud_token`, `ssh_key_fingerprint`, `ssh_allowed_cidrs`, `additional_tcp_ports`, `project_name`, `server_type`, `server_location`, `server_enable_ipv4`, `app_user`, `app_directory`, `enable_tailscale`, `tailscale_auth_key`).

**Build:**
- `infra/terraform/globals/versions.tf` - documents shared provider version constraints (reference only; each env declares its own `required_providers` block since Terraform requires it in the root module)
- `infra/terraform/globals/backend.tf` - documentation-only file describing the S3 backend setup (the real `backend "s3" {}` block lives in `infra/terraform/envs/prod/main.tf` since Terraform backends must live in the root module)
- `infra/terraform/modules/hetzner-vps/` - reusable module (SSH key lookup, firewall, server, firewall attachment) consumed by `infra/terraform/envs/prod/main.tf`

## Platform Requirements

**Development:**
- Terraform `>= 1.5`, `make`, `bash`, `ssh`/`scp`, `jq`, `terraform` CLI, and (optionally) `docker` locally for testing
- macOS/Linux shell environment (scripts assume `bash`, `set -euo pipefail`, GNU/BSD-compatible `date`, etc.)

**Production:**
- Hetzner Cloud VPS (`server_type` default `cx23`, `server_location` default `nbg1`), Ubuntu image, provisioned by Terraform + cloud-init
- Hetzner Object Storage (S3-compatible) for Terraform remote state (`bucket = "coter-tf-state"`, endpoint e.g. `https://hel1.your-objectstorage.com`)
- Optional Tailscale VPN mesh for private SSH access (`enable_tailscale`)
